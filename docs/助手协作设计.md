# 助手协作设计

## 1.0 点对点工作交接

例如，在工程助手的现有对话中输入 `@测试助手`，从候选列表选中测试助手，把协作方式切换为「交接工作」，再输入「根据当前修复结果整理回归清单」。工程助手在当前会话里总结目标、成果、待办和阻碍。输入框上方显示「交接摘要已准备 · 待发送」。用户审阅后确认，测试助手随即在自己的新会话中开展工作。原对话保留交接回执和「打开接手对话」入口。

### 交互规则

| 场景 | 行为 |
| --- | --- |
| 输入 `@` | 候选按名称匹配其他可用助手。项目中的 `@file:`、`@folder:` 仍可用于资料补全。选定的助手显示在输入框上方，可以移除。 |
| 发送交接请求 | 已有 Hermes 会话可只选助手，按当前任务整理。新会话需要提供文字或图片作为任务材料。当前助手有执行中的任务时，等该轮结束后可以发起交接。 |
| 摘要生成 | 发起助手读取当前 Hermes 会话上下文，按目标、成果、待办和阻碍组织摘要。有图片或技能时，由发起助手在本轮使用。 |
| 审阅与确认 | 审阅窗口显示将发送的任务说明、摘要和来源助手。确认后接收助手开始工作。返回原对话后，仍可从这条请求再次打开审阅。 |
| 接收和执行 | 接收助手使用自己的角色记忆、工具和默认工作区，模型和审批沿用新对话的默认设置。它收到审阅过的文字，文件、图片、完整聊天记录、工具日志和来源项目的工作目录留在来源侧。 |
| 停止和失败 | 摘要停在未完成状态，可重新发起。接收会话已建立时，重复确认会打开原接收会话。接收阶段失败时，可以在接收会话中查看错误并继续。 |

### 数据与执行

- 发起消息保存接收助手 ID、名称快照和最终交接摘要。接收会话保存来源助手及来源会话 ID，使用发起消息 ID 作为会话 ID，借助现有会话持久化实现双向跳转和重复提交识别。
- 发起和接收各走独立的 Hermes ACP 回合，复用现有的停止、工具审批和流式回复。发起阶段只有完整结束并产出最终文本时才可审阅。接收会话先保存，经用户确认后启动回复。
- 历史会话读取时，交接字段可缺省。角色名字变化时，投递仍以角色 ID 为准。

## 当前对话内的协作问答

选中 `@助手` 后可切换协作方式，默认「直接提问」。

| 协作方式 | 发送范围 | 回答位置 |
| --- | --- | --- |
| 直接提问 | 用户输入的文字问题，也可先在「附带前文」勾选最多六条文字片段 | 当前对话，显示答复助手的头像和名称 |
| 让当前助手拟问题 | A 从自己的会话整理问题，用户审阅后发送确认过的文字 | 当前对话，可将答复引用进 A 的输入框 |
| 交接工作 | 用户审阅后的任务说明和交接摘要 | 接收助手自己的新对话 |

协作问答每次使用答复助手角色指令的独立临时 Hermes Session，接收本次问题和用户勾选的前文。预览列出实际会发送的文字，每条最多 700 字；发送后可在原问题下展开查看。长期记忆、项目目录、技能和 MCP 工具不参与这一轮。当前对话保留问题、答复与来源，A 的原 Session 继续用于普通聊天。点「引用给当前助手」后，可补上自己的要求再发给 A。停止和失败会在原问题下显示，用户可以对同一问题重试。

### 助手目录

「MCP 管理」的「暖光协作」显示随应用打包的内置服务。暖光为每个角色的普通私聊自动注册 `list_roles`、`list_my_groups`、`search_group_chat`、`search_group_memory` 和 `propose_group`，调用角色由应用绑定。`list_roles` 返回其他角色的 ID、名称和简介。`list_my_groups` 返回调用角色所在的群及成员。角色改名后可以继续通过同一 ID 定位。

普通对话中提及某位助手的名字时，当前助手也会收到对应的目录匹配。可以用名字辨认对方，也可以说「先查一下还有哪些助手，推荐谁适合复查这次改动」，让 A 调用目录工具再推荐人选。

## 2.0 多助手群聊

从左侧「群聊」新建，设置群名并勾选成员，目标可以留空。直接发一条消息即可开启话题，需要指定发言者时可以用 `@`。右上角「群内新对话」会在同一群新建对话。展开左侧群名后最多显示五段对话，当前选中的旧对话会保留在预览里。点「全部对话」可以按标题检索。对话默认取首句作为标题，可右键重命名。成员和群设置共享，各段群内对话的记录、队列和 Hermes Session 独立保存。

也可以在 A 的普通对话里说「查一下助手目录，请推荐两位适合做复核和汇报的助手，拟一份建群提案」。A 可调用 `list_roles` 和 `propose_group`，写下群名、目标、成员分工和首条任务。侧栏「群聊」会标出待确认提案。用户可修改成员和任务、选择开场助手，点击「创建群聊」后才启动群聊。

- 新群和未保存发言方式的旧群默认「自然接话」。一位先回答，其他人只在有补充时接话。单独发一条链接时，默认只由一位回应。可在「聊天规则」选择「同时回应」或「依次接话」。同时回应时最多两位在独立 Hermes 进程生成，输入框上方可展开查看进度。
- 「聊天规则」的活跃度控制自动接话。安静在首轮结束，自然适量接话，热络鼓励成员继续互动。发言总数可按话题设置为 1–30 条。已选成员可在「个性」设置接话积极性、说话风格和强度。寡言成员仍能被明确点名。设置只作用于该群，并由群内各段对话共享。
- 普通话题默认最多 4 句，可设为 2、4 或 6 句。助手可以自然接话，也可以主动 `@` 同伴。定向任务默认由用户点击「请接力」，自动任务接力最多三次。同一任务中重复 `@` 已发言者要确认。
- 「主动开话题」默认关闭。开启后可选安静 15、30 或 60 分钟，旧的短间隔按至少 15 分钟执行。仅在应用前台且正在查看该群、当地时间 9–22 点、用户最近一小时参与过时触发。每群每天默认一次，可设 0–3 次；全应用合计每天最多三次。限额按持久化的已发起回合计算，失败也计入。一次只生成一条文字，允许略过；无人回应时停止，主动回合不启动接力。30 秒后请求取消。这是调用次数预算，实际 Token 与账单取决于模型和上下文。
- 「暂停队列」允许当轮完成并保留后续排队。「停止本轮」会取消当轮并暂停队列。等待中的单条任务可「移出队列」。回车发送，Shift＋回车换行；用户发送新消息或重试时恢复当前对话队列。停止操作执行期间保留输入，待停止完成后发送。
- 回形针支持图片和 UTF-8 文本，也可粘贴或拖入图片，并可只发附件。每条消息最多四份图片或资料。文本每份最多 64 KB；图片使用私聊的压缩规则，文件最大 24 MB，处理后单张最大 5 MB。图片独立保存在 `groups/images/`，群聊记录只保存引用，接话和接力时作为图片输入交给 Hermes。缩略图可点击放大。
- 用户明确点名邀请助手时，当前回合可调用 `invite_group_member`，支持「谁邀请下黄小米」等表达。用户发链接并请求打开时，当前回合可调用 `read_group_link` 查看初始 HTTP 响应。群设置可分别关闭邀请和链接读取；关闭后应用和 MCP 服务端都会检查。
- 群聊允许工具时，可分别选择终端命令、文件工具、网页搜索、浏览器操作、外部 MCP、角色技能。选择传入 Hermes 的实际工具配置；修改后在下一回合生效。终端和外部 MCP 自身可能具备文件、网络操作能力。

群聊和提案保存在暖光数据目录的 `groups/` 下。群成员运行目录与其普通对话分开，群聊的历史发言带有当时的发言者和提问者，角色改名后按稳定 ID 保留关联。

打开群聊或切换群内对话时，会提前启动成员的 Hermes 进程并建立或恢复会话，准备使用该群的工具配置。预启动不发送聊天提示；首次发言和连续聊天复用对应进程。空闲进程最多缓存八个，十分钟未使用后释放。需要当前回合专用工具的邀请等请求仍使用独立工具回合。排队成员集中显示在输入框上方的成员进度中，每位成员一行；点击排队数量可移出指定任务。

### 群记忆与历史检索

- `search_group_chat` 按群名、发言者或文字检索历史。范围限于当前助手仍为成员且实际发言过的话题。在群里调用时只查本群。私聊中的简短回顾可直接取得近期符合范围的六条文字。
- 在群里说「请记住，周五发周报」，当前助手可通过 `save_group_memory` 留一条群记忆。群记忆按群保存，群内各段对话共享。群成员可在群聊或自己的私聊中按需调用 `search_group_memory`，每次最多返回八条。普通群聊只继续积累聊天记录，助手需要旧信息时按需检索。
- 群聊发言不会自动写进角色的私聊长期记忆。群聊的 Hermes Session 使用独立的角色运行目录。运行设置开启「群聊也使用完全访问」后，可在每个群的聊天规则选择「仅聊天」或「允许工具」，并分别选择工具类别。新群默认仅聊天，已有群沿用原先设置；设置作用于后续回合。主动开话题始终使用独立的纯文字回合。
- 自然模式中普通成员在被点名后接话，设为「主动接话」的成员可主动补充并允许略过。依次接话、同时回应和热络模式保留。闲聊提示鼓励一两句直接回应，减少夸赞、复述和固定追问，保留各角色性格。
