# Hermes Studio 角色技能与文件目录规划

## 技能库与角色

建议把技能文件和角色的启用规则分开。桌面端与终端可以读取同一份已安装技能库。桌面端本次会话只读取技能说明，已配置独立角色的记忆、对话和角色指令。

| 新建角色时的选项 | 生效规则 |
| --- | --- |
| 继承已启用技能（默认） | 角色使用本机 Hermes 已启用的技能。以后安装或更新技能，继承模式随技能库更新。 |
| 仅启用所选技能 | 角色只使用勾选的技能。新安装的技能需要手动勾选。找不到已选技能时，在角色设置里标出。 |

聊天输入框内的技能选择作用于当前消息，候选范围由角色的启用选项决定。角色自建的技能可以进入其私有技能目录，其他角色需要显式导入才可使用。复制角色模板时复制指令和启用选项，新角色从空白记忆开始。

当前版本支持继承本机技能或仅启用勾选项。角色的选择保存在 `role.json`，输入框可以键入 `/` 或 `/skill` 搜索已启用技能。角色私有技能目录仍是后续设计。技能涉及的工具按桌面端当前允许的工具集运行。

## 智能创建角色

用户用自然语言说明工作场景、期望输出和偏好。桌面端向当前 Hermes 默认模型发送描述和启用技能的目录信息，由模型返回名称、简介、角色指令及推荐技能。应用只接受目录中存在的技能，将结果填入可编辑的草稿。用户确认后才保存并生成角色自己的数据目录。

角色编辑器中的「用 AI 拟定角色」使用本机 Hermes 默认模型。独立模型连接可以作为后续设置，启用后仅处理角色草稿等辅助功能。配置单独连接时应使用 HTTPS，密钥保存在系统钥匙串。

## 文件保存位置

当前版本在 macOS 的应用数据目录中保存应用管理状态。角色以 UUID 为目录名，角色改名时路径仍稳定。

```text
~/Library/Application Support/Hermes Studio/
  projects.json                      按助手登记的项目与本地目录映射
  roles/<角色 UUID>/
    role.json                        名称、简介和模板
    conversations.json               会话、消息及项目引用
    Projects/<项目名称>/             此助手新建的实体项目目录
    images/                          聊天图片
    runtime/
      SOUL.md                        角色指令
      memories/MEMORY.md             长期记忆
      memories/USER.md               用户偏好
      workspace/                     无项目对话的默认工作目录
```

项目关联到已有文件夹时，会话使用该文件夹作为工作目录，项目映射和聊天历史仍写入桌面端数据目录。今后可为可下载的会话产物加一个统一保存入口。建议项目内默认保存到 `<项目目录>/outputs/<会话>/`，无项目产物默认保存到 `~/Documents/Hermes Studio/Exports/`。首次保存时显示目标位置，用户可另存到其他文件夹。创建项目或关联目录本身只记录映射和新建所需目录。

升级时，已有项目按历史对话的助手归属登记，项目文件保留在原目录。没有对话的旧项目归给最早创建的可用助手。多个助手曾在同一旧项目中对话时，各自保留项目入口和自己的历史，入口仍指向原目录。

## 与终端 Hermes 的边界

- 桌面端每次运行 Hermes 都显式将 `HERMES_HOME` 指向当前角色的 `runtime/`。因此记忆、会话和操作运行状态位于角色自己的目录。
- 本机 Hermes 安装依赖可以共享，模型配置和已安装技能按需读取。模型密钥通过子进程环境传递，角色配置文件只保存引用。
- 点击工作台上的「终端 Hermes」进入桌面会话。第一次聊天或编辑时复制终端角色指令与记忆。卡片的「⋯」菜单可编辑桌面角色资料、头像、技能和指令，也可在「详细信息」中查看原终端的目录与记忆。
- 普通角色可移入草稿箱，保留角色资料、头像、记忆和会话 30 天。恢复沿用原角色 ID。应用运行期间定期清理过期角色，应用关闭时在下次启动后清理。

## 验收

两个角色写入不同记忆后互相切换，各自只能从自己的默认上下文取到对应内容。角色创建、发起项目对话、挂载技能和保存附件前后，终端 Hermes 的两份记忆文件保持一致。项目目录移动后，应用明确提示重新关联，历史会话保留。
